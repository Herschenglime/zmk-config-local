# ZMK config: Cradio

ZMK firmware config for a 34-key split keyboard (`nice_nano_v2`, shield `cradio`), built with Nix.

![Keyboard layout](docs/layout.svg)

The diagram is generated by [docs/gen_layout_svg.py](docs/gen_layout_svg.py). If `config/cradio.keymap` changes, have an LLM update the data in that script and regenerate the SVG.

## Build and flash

Firmware is built and flashed locally with Nix using [zmk-nix](https://github.com/lilyinstarlight/zmk-nix). The workflows in `.github/` are not enabled; this repo does not build in CI.

On a non-NixOS machine, enable flakes first:

```bash
mkdir -p ~/.config/nix
echo "experimental-features = nix-command flakes" >> ~/.config/nix/nix.conf
```

### Build

```bash
nix build
```

This writes one `.uf2` per half (`*_left.uf2`, `*_right.uf2`) to `./result`.

### Flash

```bash
nix run .#flash            # both halves, one after the other
nix run .#flash -- left    # a single half
```

This builds the firmware first, so a separate `nix build` isn't needed. For each half, the script will:

1. Ask you to double-tap reset and plug that half in over USB (this puts the nice!nano in UF2 bootloader mode).
2. Detect the `nRF UF2` drive and mount it with `udisksctl` (`sudo apt install udisks2` if missing). If it can't mount, mount the drive manually anywhere.
3. Copy that half's `.uf2` onto it. The board reboots on its own once the copy finishes.
4. Wait for you to unplug it before moving on.

## Resetting and bootloader mode

Combos are described by key position, since the keys have no legends. The diagram at the top shows every combo as a small keyboard with the keys to press highlighted. `·` is any other key; each half's top row runs from the outer edge (pinky) to the inner edge (index).

```
  left half     right half
  · R R B B  |  B B R R ·     R = reset combo, B = bootloader combo
  · · · · ·  |  · · · · ·
  · · · · ·  |  · · · · ·
```

- **Reboot a half:** press the four `R` keys together on the default layer: the second and third keys from the outer edge on each half's top row (`&sys_reset`).
- **Enter the bootloader from the keyboard:** press the four `B` keys together on the default layer: the two innermost top-row keys on each half (`&bootloader`). The NUM layer (hold both outermost thumb keys) also has a `Boot` key: the innermost key of the left half's bottom row. The half then shows up as the `nRF UF2` drive, ready for flashing.
- **If the keyboard isn't responding:** on the nice!nano, short the `RST` and `GND` pins together twice in quick succession (a double tap). One short is just a reset. Two quick ones enter the bootloader.
- **Bluetooth trouble:** press the whole outer column of the left half (top, home and bottom keys) together to toggle the Bluetooth layer. Then pick a profile or clear the current one, and re-pair the host:

```
  T · · · ·  |  · · · · ·     T = Bluetooth layer toggle (press all three)
  T · · · ·  |  · 0 1 2 3     0-3 = Bluetooth profiles 0-3
  T · · · ·  |  · 4 C S ·     4 = profile 4, C = clear current profile, S = Studio unlock
```

Each half is reset or put in the bootloader separately, so do it on the half you're working on.

## Pinned versions

Everything is pinned so the build stays reproducible until you choose to move it:

- **ZMK v0.3** (Zephyr 3.5, the latest stable release): `config/west.yml` pins both `zmk` and `zephyr` by commit hash. The comments after each hash (`# v0.3-branch`, `# v3.5.0+zmk-fixes`) are for the zmk-nix update script, which this repo doesn't use. Don't run `nix run .#update`: it would move the ZMK pin to the current head of that branch.
- **nixpkgs and zmk-nix**: pinned by `flake.lock`. Only `nix flake update` or `nix flake lock --update-input <name>` changes them.
- **`zephyrDepsHash`** in `flake.nix` is the hash of the dependencies `west.yml` fetches. It only changes if `west.yml` does. After editing `west.yml`, set it to `""`, run `nix build`, and copy the hash from the "got:" line of the error.

`flake.nix` differs from the [zmk-nix template](https://github.com/lilyinstarlight/zmk-nix/tree/main/template) in a few places: the cradio shield, `enableZmkStudio`, `extraCmakeFlags` (for `compile_commands.json`), and a `setuptools_80` build input. ZMK v0.3's Studio code imports `pkg_resources`, which current nixpkgs setuptools no longer ships.

### Moving to a newer ZMK

ZMK `v0.4` (Zephyr 4.1) is not released yet. When it is, the board name changes (`nice_nano_v2` becomes `nice_nano@2.0.0//zmk` or similar), so check zmk-nix's template for the exact form, bump the pins in `west.yml`, and update `zephyrDepsHash`. The `setuptools_80` input can likely be dropped then. See ZMK's [Zephyr 4.1 post](https://github.com/zmkfirmware/zmk/blob/main/docs/blog/2025-12-09-zephyr-4-1.md) for the breaking changes.
